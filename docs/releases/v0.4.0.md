# ResampleOS 0.4.0

Sends, and a sample browser that knows your samples. Every pad can now send to any other bus, so one reverb or delay can be shared. The sample browser analyses your folders in the background: a loop's tempo and key, a one-shot's note, every file's length. You can filter on all of them, and audition loops in time with the project. Together with 0.3.5's browser, MIDI files, stems and freeze, this completes 0.4. Projects from 0.3 open as they were.

> **Pre-release.** Developed and tested on Windows 11 only. Expect rough edges, and save often.

## New

### Sends

- **Sends** beside a pad's **Bus** gives it a level to each of Bus 1 to 4 and Bus V, from off to 0 dB. Put a reverb or a delay on a bus at full mix, send pads to it, and they share one space.
- Sends are taken after the pad's volume and pan, so they follow its fader and its mute. They work for every kind of pad and for audio clips on the song timeline.
- Song export and stems include them: each pad's sends come out in its own stem. Consolidate and freeze render the pad dry, so the result still feeds its sends when it plays.

### The sample browser, continued

- **Analysis.** Each file in your sample folders is analysed in the background: its length, and a loop's tempo and key or a one-shot's note. The results show beside each file ("92 BPM · Am", "E2 · 0.4 s"). They are kept in the settings folder, so a file is only analysed again if it changes. The browser's footer shows how many files are left.
- **Filters:** one-shots or loops; a key (the project's or any other, with related keys counted for loops and in-key notes for one-shots); a tempo range; a longest length. A filter searches every folder at once.
- **Sync** auditions loops stretched to the project tempo. They go round until you pick another file, and while the transport runs they start on the next beat, so you hear them in time with the song.
- **Project** lists the audio files of the open project.
- Sample folders can also be added and removed under **Sample folders** in Preferences.
- While a file is dragged, its label says where it will land, and the pad under it is outlined.

### From 0.3.5, for anyone coming from 0.3.0

- The sample browser (**Samples** or `F4`): your folders beside the pads or the timeline, search, favourites, recent files, auditioning, and dragging onto pads or the timeline.
- MIDI files in and out: onto pads or the timeline, and a pad or the whole song out.
- **Stems** by track or by bus, and **Freeze** for a track.

See the [0.3.5 release notes](v0.3.5.md) for more.

## Install

**From the download:** unzip `ResampleOS-0.4.0-windows-x64.zip` and run `resampleos.exe`. There is no installer and nothing is written outside the folder except settings (and the sample browser's analysis cache) in `%APPDATA%\ResampleOS`. Windows may show a SmartScreen warning because the program is not signed: choose **More info**, then **Run anyway**. If it reports a missing `VCRUNTIME140.dll`, install the [Microsoft Visual C++ Redistributable](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist).

**Upgrading from 0.3:** replace the folder. Settings and projects carry over; sample folders added in 0.3.5 are analysed the first time the browser opens. A project saved in 0.4.0 opens in 0.3.x without its sends.

**From source:** you need [Rust](https://rustup.rs) 1.88 or newer and the MSVC build tools.

```bash
git clone https://github.com/DamonianoStudios/ResampleOS
cd ResampleOS
cargo run --release -- showcase/built-in-boom-bap
```

The [user guide](https://github.com/DamonianoStudios/ResampleOS/blob/v0.4.0/docs/USER_GUIDE.md) covers sends under Buses and effects, and the browser's analysis, filters and Sync in its sample browser section. The [roadmap](https://github.com/DamonianoStudios/ResampleOS/blob/v0.4.0/docs/ROADMAP.md) has what comes next.

## Known limitations

- Sends go only to the existing four buses and Bus V; there are no separate return tracks yet, and the buses are still fixed at four with three slots each. Return tracks and more buses are planned for 0.5.
- Sends are post-fader only, and can't be automated yet.
- Sync auditions follow the project tempo but not its key.
- Tempo and key detection in the browser are estimates. They are reliable for clear loops, but can be wrong on sparse, ambient or very short files. A file whose key the analysis is unsure of shows no key, and is left out by a key filter.
- Analysing a large library takes a while the first time (a file at a time, in the background). Files over 80 MB are listed but not analysed.
- Everything listed for 0.3 still applies: Windows only, VST3 and CLAP only, one tempo in 4/4, no plugin delay compensation, no ASIO, plugins not crash-isolated.
- The new features were checked by tests and on screen, and have not been listened to critically.
